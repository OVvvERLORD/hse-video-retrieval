# Разработка информационного поиска видео на основе текстового запроса 🎬🔍

Мультимодальная система семантического поиска видеоконтента по текстовому описанию на основе эмоционального окраса.

## Общая схема

Система работает по принципу двухпотоковой мультимодальной обработки:

### 1. Онлайн-обработка текстового запроса (Prompt)
* **Вход**: Текстовый запрос от пользователя.
* **Поток 1 (Эмоции)**: Запрос -> Классификатор эмоций -> Определение Top-3 доминирующих эмоций.
* **Поток 2 (Смысл)**: Запрос -> Текстовый эмбеддер -> Получение вектора запроса (float32).
* **Выход**: Фильтрация базы по эмоциям -> KNN-поиск по косинусному расстоянию -> Выдача **Top-K видео**.

### 2. Офлайн-индексация корпуса видео (Подготовка)
* **Вход**: Исходный корпус видеоклипов.
* **Поток 1 (Эмоции)**: Видео -> Видео-классификатор (VideoMAE) -> Метки эмоций для каждого видео.
* **Поток 2 (Смысл)**: Видео -> Видео-эмбеддер (V-Jepa 2) -> Векторы визуальных признаков.
* **Выход**: Формирование единого векторного индекса (хранилище меток и векторов).

## Стек

### Текстовые эмбеддинги
В ходе эволюции проекта исследованы три подхода к векторизации текста: **TF-IDF -> Word2Vec -> BERT**.
* **Дообучение текстовых эмбеддингов**: Использован энкодер `BERT` с обучением через функцию потерь `OnlineContrastiveLoss` и применением стратегии **online hard-mining**.

### Классификатор текста
Для извлечения эмоций из текстового запроса спроектирована полносвязная нейросеть (MLP) со следующей топологией:
* **Входной слой**: Вектор размерности `768` (BERT-эмбеддинг).
* **Скрытый блок 1**: `Linear(768 -> 256)` -> `LayerNorm(256)` -> `ReLU` -> `Dropout(0.3)`.
* **Скрытый блок 2**: `Linear(256 -> 48)` -> `LayerNorm(48)` -> `ReLU` -> `Dropout(0.2)`.
* **Выходной слой**: `Linear(48 -> 8)` -> Выход из 8 логитов.

### Анализ видео
Обработка видеопотока реализована в двух вариациях:
1. **Каскадный подход (VLM + Текст)**: Видеоклип -> VLM-модель (генерация описания) -> Текстовый эмбеддинг -> Классификатор (MLP + Softmax) -> Итоговая эмоция.
2. **End-to-End подход (Прямая классификация)**: Дообученная архитектура **VideoMAE** для прямого извлечения признаков и эмоций из сырого видеоряда без промежуточной генерации текста. На кросс-валидации дообученная VideoMAE значительно превзошла дефолтную модель по метрикам Accuracy и Macro F1.

### Хранение данные 
* Первичный отбор кандидатов осуществляется фильтрацией базы данных по предсказанным эмоциям.
* Быстрый поиск ближайших соседей (KNN) в пространстве эмбеддингов реализован через векторный индекс библиотеки **usearch** по косинусному расстоянию.
* Метаданные и векторы упакованы в файлы **Parquet** сжатием `zstd` для быстрой потоковой записи и чтения.

## Используемые корпуса
* **EmoVid**: Основной видеокорпус для поиска, размеченный по 8 классам эмоций. Подписи (captions) получены с помощью VLM-модели (средняя длина описания — 54.7 слов).
* **GoEmotions**: Датасет от Google (27 эмоций, сгруппированных в 8 групп). Применялся для тонкой настройки классификаторов и разведочного анализа текстов (down-sampling до баланса классов в T = 9245 объектов).
* **Синтетические emoted-captions**: Корпус, сгенерированный с помощью LLM для оценки качества базовых моделей.

## Сравнения

### Классификация текста
По результатам сравнительного анализа, нейросетевые модели значительно превзошли классический ML (`LogReg`, `LightGBM`, `Random Forest`) и LLM (`Qwen3.5-4B` с few-shot промптинг через Unsloth):
* **Лидеры по качеству**: `Linear BERT (base)` и `Linear BERT (fine-tuned)` продемонстрировали наивысшие значения Macro F1 (~0.85–0.87), сохранив идеальный баланс Precision/Recall. 
* Классический бейзлайн `SVC + W2V (base)` показал высокую общую точность (Accuracy 0.88), но полностью провалился на минорных классах (например, класс *anger* / *disgust* имел F1-score близкий к 0.00).

## План развития
1. **Переход на V-JEPA**: Замена текущего видеоэнкодера на передовую архитектуру `V-JEPA` (Video Joint Embedding Predictive Architecture) от Meta для получения более мощных визуальных представлений.
2. **Оптимизация пространства поиска**: Глубокое исследование метрик сходства в пространстве `usearch`.
3. **Краудсорсинг**: Доработка интерфейса приложения для ручной валидации и сбора оценок релевантности поиска пользователями.
